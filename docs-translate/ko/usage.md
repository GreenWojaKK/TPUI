## 파일 열기

- 명령줄로 받은 파일은, Windows가 뷰어에 연결된 파일을 여는 경우를 포함해 같은 방식으로 연다. Windows에서 뷰어가 이미 실행 중이면 그 뷰어의 탭으로 열고 창을 앞으로 가져오며, 한꺼번에 연 여러 파일은 한 창을 함께 쓴다. 파일 없이 뷰어를 시작하면 창을 하나 더 연다.
- `Open File` 또는 `Ctrl+O`로 네이티브 파일 선택창을 연다. 취소하면 현재 상태를 유지한다.
- 확장자가 `.md`, `.markdown`, `.json`, `.jsonl`, `.pdf`이거나 [코드 확장자](#코드-문서)인 파일은 [문서](#markdown-문서)로 연다. 선택한 파일에 SQLite 헤더가 있으면 이름순으로 첫 번째 테이블 또는 뷰를 열고, 탐색기에서 데이터베이스를 펼쳐 나머지를 표시한다. 테이블이 없는 데이터베이스는 상태 표시줄에 알림을 표시한다. 그 밖의 파일은 확장자와 관계없이 Parquet 리더로 검증한다.
- 새 소스를 열면 탭을 생성하고 활성화한 뒤 화면에 표시할 소스를 읽는다. 소스는 Parquet 파일, 문서, 또는 SQLite 데이터베이스와 테이블 이름의 조합이다. 이미 탭으로 열린 소스라면 해당 탭을 활성화한다. SQLite 탭 제목은 `table · file name`이다.
- Parquet은 첫 화면의 데이터를 읽기 전에 footer와 메타데이터에서 행 수와 스키마를 얻는다. SQLite 테이블을 열 때는 저장된 타입과 행 위치를 확인하기 위해 행도 조사한다.
- 파일을 직접 열었을 때 탐색기 루트가 없으면 부모 디렉터리를 탐색기 루트로 지정한다. 기존 루트가 있으면 유지한다.
- Windows에서 파일을 연결하려면 viewer 실행 파일들을 고정된 폴더에 두고 해당 형식의 `연결 프로그램 → 다른 앱 선택`에서 `viewer-app.exe`를 선택한다.

## 탐색기

- `Open Folder`로 루트 디렉터리를 선택한다. 폴더를 펼치면 직계 자식만 나열한다.
- 디렉터리, 확장자가 `.parquet`, `.md`, `.markdown`, `.json`, `.jsonl`, `.pdf`이거나 [코드 확장자](#코드-문서)인 파일, SQLite 데이터베이스를 표시한다. 데이터베이스는 확장자가 `.sqlite`, `.sqlite3`, `.db`, `.db3`, `.s3db`, `.sl3` 중 하나이고 SQLite 헤더로 시작하는 파일이다. 그 밖의 `.db` 파일은 숨긴다. 확장자는 대소문자를 구분하지 않는다.
- 데이터베이스를 펼치면 테이블, 뷰, 가상 테이블을 이름순으로 나열한다. 내부 `sqlite_` 테이블과 가상 테이블의 shadow 테이블은 제외한다. 뷰에는 `view` 표시를 붙인다.
- 디렉터리를 먼저 표시하고, 같은 종류 안에서는 이름순으로 정렬한다. 심볼릭 링크와 디렉터리 junction은 자동으로 따라가지 않는다.
- Parquet 파일, 문서, 테이블을 더블클릭하거나 선택 후 Enter를 누르면 탭으로 연다. 폴더나 데이터베이스는 한 번 클릭하면 펼쳐진다.
- 폴더 조회에 실패하면 해당 노드에 오류와 재시도를 표시한다. 이미 열린 파일의 그리드는 유지한다.

## 화면 개요

도구 모음에서 파일·폴더를 열고 테마를 바꾼다. 탐색기는 파일과 데이터베이스 객체를 나열한다. 탭으로 활성 소스를 선택하며 소스 종류에 따라 본문과 보조 패널을 표시한다.

| 활성 소스 | 본문 | 보조 패널 |
|---|---|---|
| 코드 | 소스 줄과 줄 번호 | 문서 영역 전체 폭 사용 |
| Markdown | 서식 있는 문서 | 문서 영역 전체 폭 사용 |
| JSON과 JSON Lines | 펼칠 수 있는 트리 | 선택한 노드의 Value 패널 |
| Parquet과 SQLite | 데이터 그리드 또는 저장 구조 | Schema·Value 패널 |
| PDF | 뷰 너비에 맞춘 페이지 | 문서 영역 전체 폭 사용 |

상태 표시줄은 활성 경로, 파일별 정보와 읽기 상태를 표시한다. 탐색기와 탭으로 공통 탐색을 수행하며 형식별 조작은 아래에서 설명한다.

## 탭

- 탭을 클릭해 파일을 전환한다. `Ctrl+Tab`과 `Ctrl+Shift+Tab`으로 탭 사이를 이동하고 `Ctrl+W`로 활성 탭을 닫는다.
- 탭을 드래그해 순서를 바꾼다. 화면 밖 탭으로 옮기려면 드래그한 탭을 가장자리에서 유지한다. 넘치는 탭 바는 휠로 스크롤한다.
- 탭에 마우스를 올리면 전체 경로를 표시한다.
- 데이터 탭은 그리드 위치·선택·스키마 펼침·행 뷰를 기억한다. 문서 탭은 읽던 위치를, JSON은 펼친 값과 선택한 경로도 기억한다.
- 활성 탭을 닫으면 오른쪽 탭을 선택하고 오른쪽에 없으면 왼쪽 탭을 선택한다.

## 문서와 소스 코드

### 코드 문서

- 다음 확장자 파일은 전체 폭을 쓰는 자체 탭에 코드로 열린다: `.py`, `.pyi`, `.go`, `.rs`, `.ts`, `.tsx`, `.mts`, `.cts`, `.js`, `.jsx`, `.mjs`, `.cjs`, `.c`, `.h`, `.cc`, `.cpp`, `.hpp`, `.cs`, `.java`, `.kt`, `.swift`, `.lua`, `.php`, `.rb`, `.css`, `.html`, `.xml`, `.sql`, `.sh`, `.bash`, `.ps1`, `.toml`, `.yaml`, `.yml`.
- Python, Go, Rust, JavaScript, TypeScript는 구문 색상을 표시하며 나머지 지원 확장자는 일반 텍스트로 표시한다. 코드를 열어도 실행하지 않는다.
- 각 줄은 한 행에 표시한다. `Shift`와 휠로 가로 스크롤한다. 매우 긴 줄에는 생략한 길이를 표시하며, 이 표시까지 선택하면 줄 전체를 복사한다.
- 드래그로 텍스트를, 더블클릭으로 단어를, 세 번 클릭으로 줄을 선택한다. `Ctrl+A`는 파일 전체를 선택하고 `Ctrl+C`는 원본 줄 끝을 유지해 선택을 복사한다.
- 방향키, `Page Up`, `Page Down`, `Ctrl+Home`, `Ctrl+End`로 문서를 스크롤한다.
- 토큰 서비스를 실행할 수 없으면 상태 표시줄에 이유를 표시하고 일반 텍스트로 계속 읽는다. NUL byte가 있는 파일은 바이너리로 안내한다.

### Markdown 문서

- `.md` 또는 `.markdown` 확장자 파일은 문서로서 별도 탭에 열린다. 본문은 가운데 정렬한 단에 표시하고 측면 패널은 표시하지 않는다.
- 텍스트는 공백과 줄바꿈에서만 끊으므로 한글 단어가 나뉘지 않으며, 줄 전체보다 긴 단어만 글자 사이에서 끊는다.
- 제목, 문단, 굵게, 기울임, 취소선, 인라인 코드, 글머리표·번호·할 일 목록, 인용, 열 정렬을 포함한 표, 코드 블록, 구분선, 각주, 맨 위의 메타데이터 블록을 그린다.
- 코드 블록은 공백과 줄을 유지한다. 긴 줄은 다음 줄로 이어지고, 탭은 4칸 단위의 다음 위치까지 그리며, 복사하면 원본 텍스트를 얻는다.
- HTML, 수식, 이중 대괄호 안의 텍스트는 적힌 그대로 표시한다.
- 문단에 혼자 있는 이미지는 단 너비까지 그린다. 경로는 문서 기준 상대 경로 또는 절대 경로다. 읽을 수 있는 PNG, JPEG, WebP, GIF를 표시하고 그 밖에는 대체 텍스트를 표시한다. 웹 주소의 이미지는 대체 텍스트와 주소를 표시한다.
- `http`, `https`, `mailto` 링크를 클릭하면 브라우저에서 연다. 그 밖의 링크 대상은 링크 모양으로 표시하고 이동하지 않는다.
- 드래그로 여러 블록에 걸쳐 텍스트를 선택하고, 더블 클릭으로 단어를, 세 번 클릭으로 텍스트 전체를 선택한다. `Ctrl+A`는 문서 전체를 선택하고 `Ctrl+C`는 선택을 일반 텍스트로 복사하며 표의 칸은 탭으로 구분한다.
- 방향키, `Page Up`, `Page Down`, `Ctrl+Home`, `Ctrl+End`로 스크롤한다. 세로 스크롤바가 문서를 따라간다.

### JSON 문서

- `.json` 확장자 파일은 트리로 열린다. 객체와 배열은 클릭하거나 방향키와 `Enter`로 펼친다. 큰 배열과 객체는 자식을 펼칠 수 있는 범위로 묶는다.
- 키는 중복을 포함해 파일의 순서를 유지하고 숫자는 적힌 그대로 유지한다. `1.10`은 `1.10`으로 표시한다.
- Value 패널은 선택한 값의 문서 내 위치(`$.routes[3].name` 등), 타입, 전체 텍스트를 표시한다. `Ctrl+C`는 문자열을 따옴표와 이스케이프 없이, 그 밖의 값을 파일에 적힌 그대로 복사한다.
- 파일은 RFC 8259가 정의한 JSON이어야 한다. 주석이나 끝의 쉼표가 있는 파일은 이유를 줄과 문자 열 번호와 함께 표시한다.

### JSON Lines 문서

- `.jsonl` 확장자 파일은 줄마다 JSON 값 하나가 있는 줄 트리로 열린다. 각 행은 파일의 줄 번호와 그 줄의 텍스트를 표시한다. 빈 줄은 건너뛰고 긴 파일은 줄을 펼칠 수 있는 범위로 묶는다.
- 줄을 클릭하면 값이 펼쳐지며 JSON 문서와 같이 읽는다. Value 패널은 위치를 `line 12: $.routes[3].name`처럼 표시한다.
- 올바른 JSON이 아닌 줄은 오류 색으로 제자리에 남고 다른 줄은 계속 읽을 수 있다. 선택하면 Value 패널에 이유와 문자 열 번호를 표시하고, 상태 표시줄은 이런 줄의 수를 표시한다.
- `Ctrl+C`는 줄을 파일에 있는 그대로 복사하고, `file` 행에서는 파일 전체를 복사한다.

### PDF 문서

- Windows에서 PDF 페이지를 뷰 너비에 맞춰 세로로 표시한다. 페이지 보기와 스크롤을 지원하며 확대·텍스트 선택·찾기·링크는 제공하지 않는다.
- 휠, 방향키, `Page Up`, `Page Down`, `Ctrl+Home`, `Ctrl+End`로 스크롤한다. 상태 표시줄에는 전체 페이지 수와 현재 페이지를 표시한다.
- 읽기나 렌더링에 실패하면 이유를 표시한다. `Retry`는 문서를 다시 읽고 필요하면 worker를 다시 시작한다.

### 문서를 읽는 방식

- 활성 문서는 저장된 파일 변경을 반영하고 다시 읽은 뒤 읽던 위치를 복원한다.
- 읽기에 실패하면 이유와 `Retry`를 표시한다. 파일 확인을 계속하므로 이후 저장한 변경도 반영할 수 있다.
- 텍스트 파일은 UTF-8이어야 하며 UTF-8 byte order mark를 허용한다. JSON·JSON Lines 파일은 4 GiB 미만이어야 한다.
- 찾기·필터·정렬·질의는 Parquet과 SQLite에 적용한다. 문서 탭에서 `Ctrl+F`와 질의는 안내를 표시한다.

### 편집기에서 열기

Markdown이나 코드 문서를 오른쪽 클릭하고 `Open in Editor`를 선택한다. 선택 시작 위치에서 파일을 열며, 선택이 없으면 오른쪽 클릭한 위치에서 연다. Markdown은 원본 텍스트의 위치를 사용하며 텍스트 밖을 클릭하면 파일 시작 위치에서 연다.

`$VISUAL`, `$EDITOR` 순서로 설정한 편집기를 사용한다. 설정이 없으면 Windows는 연결 앱 또는 Notepad를, Linux는 `xdg-open`을 사용한다.

| 커서 이동 | 편집기 |
|---|---|
| 행과 열 | vim, Neovim, nano, gedit, Emacs, VS Code, VSCodium, Cursor, Notepad++ |
| 행 | vi |
| 파일 시작 | 그 밖의 편집기 |

터미널 편집기는 별도 터미널 창에서 연다. Linux는 `$TERMINAL`로 터미널을 지정하며 설정이 없으면 설치된 터미널을 자동 선택한다. 편집기에서 저장하면 열린 문서에 반영한다. 실행 실패는 상태 표시줄에 표시한다.

## Parquet과 SQLite

이 탭은 데이터 그리드, 스키마, 전체 값과 저장 구조를 제공한다. 찾기·필터·정렬로 원본 행을 찾고 표시할 행과 순서를 정한다.

### 스키마 조회

- Arrow 스키마의 필드 이름, 데이터 타입, null 허용 여부를 표시한다.
- `Struct`, `List`, `Map` 필드를 펼쳐 자식 타입을 조회한다.
- 그리드 컬럼은 최상위 필드다. 중첩 필드를 펼쳐도 그리드의 컬럼 수와 행 수는 바뀌지 않는다.
- 파일 요약에는 전체 행 수, 최상위 컬럼 수, Row Group 수, 파일 크기를 표시한다.
- 행이 0개인 파일도 스키마와 컬럼 헤더를 표시하고, 본문에는 빈 데이터 상태를 표시한다.

### 데이터 그리드

- 고정 높이 행, 고정 너비 컬럼, 고정 헤더와 행 번호 영역을 사용한다.
- 세로·가로 스크롤바, 마우스 휠, Shift+휠을 통한 가로 이동을 제공한다.
- 클릭하면 셀 하나를 선택하고 강조한다. 선택한 셀은 값 상세 조회의 대상이 된다.
- 그리드에 포커스가 있을 때 방향키로 선택한 셀을 행·열 방향으로 이동한다. Page Up/Down은 화면 단위로 이동하고, Ctrl+Home/End는 첫 행·마지막 행으로 이동한다.
- 읽기 중인 셀에는 placeholder를 표시하고 데이터가 도착하면 갱신한다.
- 셀은 값의 한 줄 미리보기다. 줄바꿈, 탭, 제어 문자는 표시 기호로 바꾸고, 긴 값은 미리보기 길이에서 생략 부호를 붙인다. 원본 값 전체는 값 상세 조회에 표시한다.

### 값 상세 조회

- 셀을 선택하면 Value 패널에 전체 값을 표시한다. 문자열은 줄바꿈을 유지하고 Binary는 hex dump로 표시한다. 셀이 화면 밖으로 이동해도 값을 유지한다.
- `Struct`·`List`·`Map`을 펼쳐 자식 값을 선택한다. 패널에는 원본 행·컬럼·타입·값 크기를 표시한다.
- `Ctrl+C`로 선택한 셀이나 노드를 복사한다. 문자열은 원문, Binary는 소문자 16진수, Null은 `null`, 그 밖의 scalar는 표시 텍스트를 복사한다. 중첩 값은 JSON으로 복사하며 Map 항목은 key/value 객체가 되고, 중첩 Binary·유한하지 않은 수·시간 값은 문자열이 된다.

### 행 뷰

- 각 탭에는 필터 조건과 정렬 키가 있다. 두 가지가 그리드에 표시할 행과 순서를 결정하며, 이를 행 뷰라고 한다. 필터와 정렬이 없으면 행 뷰는 원본 파일의 행 순서를 따른다.
- 그리드의 행 위치, 스크롤, 선택, 키 이동은 행 뷰 순서를 따른다. 행 번호 영역과 Value 패널에는 원본 파일의 행 번호를 표시한다.
- 필터나 정렬을 바꾸면 worker가 새 행 뷰를 만든다. 생성 중에는 그리드에 이전 행 뷰를 계속 표시하고, 그리드 위 필터 및 정렬 바에 진행률과 `Cancel`을 표시한다. 완료되면 새 행 뷰의 첫 행으로 이동하고 선택을 해제하며, 가로 스크롤 위치는 유지한다. `Cancel`은 변경 전 조건을 복원한다.
- 조건이 있으면 필터 및 정렬 바를 표시하며 질의 텍스트 형태로 읽힌다. 각 조건과 정렬은 `×`로 제거하는 칩이고, 연산자는 `▾`가 있는 상자이며, `or`로 연결된 조건은 괄호로 묶는다. `Copy Query`는 찾기 바가 열려 있을 때 찾기 값을 포함한 질의 전체를 복사하고, `Clear All`은 원본 순서로 돌아간다. 상태 표시줄에는 행 뷰의 행 수와 전체 행 수를 함께 표시한다.
- 각 탭은 행 뷰를 기억한다. 탭을 전환해도 조건과 결과는 유지된다.

### 찾기

- `Ctrl+F`로 활성 탭의 조건과 `find` 줄이 들어 있는 질의 창을 열고 커서는 `find` 뒤에 둔다. 질의 창이 없는 시스템에서는 메시지 파일을 안내한다. 값은 셀 컨텍스트 메뉴의 `Find` 또는 질의의 `find` 줄로도 전달할 수 있다.
- 그리드 위 찾기 바에는 찾는 값, 질의 창을 다시 여는 `Change…`, `Previous`, `Next`, 상태, `×`를 표시한다. 그리드에서 `Esc`를 누르면 찾기 바를 닫는다.
- 찾기는 값 전체가 입력과 정확히 같은 셀을 찾는다. 대소문자를 구분한다.
- 찾기는 표시하는 전체 값을 비교한다. 문자열은 원문, 숫자·시간·Boolean은 표시값, Binary는 16진수를 사용한다. 16진수 입력은 대소문자를 구분하지 않는다. Null 셀과 `Struct`, `List`, `Map` 셀은 찾기 대상이 아니다.
- `F3`와 `Next`는 다음 일치 항목으로, `Shift+F3`와 `Previous`는 이전 항목으로 이동한다. 순서는 행 뷰의 행 순서 다음에 행 내부 컬럼 순서다. 선택한 셀에서 검색을 시작하고 끝에 도달하면 처음으로 돌아간다.
- 찾은 셀을 선택하고 보이도록 스크롤한다. 찾기 바에는 전체 행 뷰에서 일치하는 셀 수를 표시하고 그리드에서는 일치하는 셀을 강조한다.
- 셀 컨텍스트 메뉴의 `Find`는 셀의 전체 값을 찾기 바에 넣고 다음 일치 항목으로 이동한다.
- 새 값을 처음 검색하면 파일을 읽어 일치 위치를 계산한다. 계산 중 찾기 바에 진행률을 표시하며 그리드 스크롤, 셀 선택, 탭 전환은 계속 동작한다.
- 새 조건과 함께 보낸 찾기는 해당 조건이 적용된 뒤 실행한다. 조건 적용 중 `F3`를 누르면 찾기 바에 알림을 표시한다. 탭을 전환하면 새 탭의 찾기 결과를 다시 계산한다.

### 컨텍스트 메뉴

- 컬럼 헤더를 오른쪽 클릭하면 `Sort Ascending`, `Sort Descending`, 정렬된 컬럼의 `Clear Sort`, `Only Nulls`, `Exclude Nulls`, 조건이 있는 컬럼의 `Remove Conditions on This Column` 메뉴를 연다.
- 셀을 오른쪽 클릭하면 선택한 뒤 전체 값을 읽었을 때 메뉴를 연다. 값이 있는 셀은 컬럼과 해당 값을 비교하는 조건(`=`, `≠`, 컬럼 타입에 따라 `>`, `≥`, `<`, `≤`), `Find`, `Copy Value`를 제공한다. Null 셀은 `Only Nulls`와 `Exclude Nulls`를 제공한다. 중첩 값에는 조건을 제공하지 않는다.
- 조건 항목은 보조 키에 따라 동작한다. Shift+클릭은 컬럼의 조건을 `or`로 연결하고, Alt+클릭은 반대 조건을 추가한다.
- 조건에는 셀의 전체 값을 사용한다. 값 텍스트는 셀의 복사 텍스트다. 문자열은 그대로, Binary는 소문자 16진수, 그 밖의 값은 표시한 텍스트이며 같은 값으로 다시 파싱된다.
- 항목을 선택하면 적용하고 메뉴를 닫는다. 바깥을 클릭하거나 `Esc`를 누르면 동작 없이 메뉴를 닫는다.

### 필터

- 조건은 컨텍스트 메뉴와 질의 텍스트에서 가져온다(아래 참조).
- 필터는 스프레드시트 필터와 같은 형태다. 모두 만족해야 하는 절을 `and`로 연결한다. 하나의 절은 같은 컬럼에 대한 하나 이상의 조건 중 적어도 하나를 만족해야 하며 `or`로 연결하고, 여러 조건이면 괄호로 표시한다. 예: `(OBE_ID == "366" or OBE_ID == "977") and id >= 5 and id < 20`. 따라서 `or`는 같은 컬럼의 조건만 연결하며 괄호는 중첩되지 않는다.
- 같은 컬럼의 절은 해당 컬럼이 처음 등장한 순서에 따라 이웃하게 배치한다.
- 메뉴의 조건은 같은 컬럼의 다른 절 뒤에 `and`로 추가한다. Shift를 누르면 해당 컬럼의 마지막 절에 `or`로 합친다. 컬럼에 이미 `=` 조건이 있으면 새 `=` 조건은 Shift 없이도 그 절에 `or`로 합친다. 서로 다른 두 값을 `and`로 연결하면 일치하는 행이 없기 때문이다.
- 필터 및 정렬 바의 연산자 상자는 `and`와 `or`를 전환한다. 괄호 안에서 `and`를 선택하면 그 지점에서 절을 둘로 나누고, 같은 컬럼의 두 절 사이에서 `or`를 선택하면 합친다. 서로 다른 컬럼의 절 사이에서는 `and`만 선택할 수 있다.
- 읽는 순서대로 조건을 가로질러 드래그하면 범위를 선택한다. 조건 위에서 놓으면 범위 전체를 정확히 하나의 절로 만들고 내부는 `or`, 바로 바깥 조건과는 `and`로 연결한다. 조건 하나 또는 여러 컬럼에 걸친 범위는 아무것도 바꾸지 않는다. `Esc`를 누르거나 다른 곳에 놓으면 범위 선택을 취소한다. 드래그 중에는 놓았을 때의 동작을 바에 표시한다.
- 연산자는 컬럼 타입에 따라 달라진다.

| 컬럼 타입 | 연산자 |
|---|---|
| 문자열 | `=`, `≠`, `contains`, `<`, `≤`, `>`, `≥`, `null`, `not null` |
| Boolean, 정수, 실수, Decimal, Date, Time, Timestamp | `=`, `≠`, `<`, `≤`, `>`, `≥`, `null`, `not null` |
| Binary | `=`, `≠`, `null`, `not null` |
| `Struct`, `List`, `Map` 및 그 밖의 타입 | `null`, `not null` |

- 비교 연산자의 값은 컬럼 타입으로 파싱하고 값으로 비교한다. 예를 들어 Decimal 컬럼의 `= 1.5`는 `1.50`과 일치한다. 파싱할 수 없는 값은 적용하지 않고 필터 및 정렬 바에 이유를 표시한다.
- 문자열 비교와 `contains`는 대소문자를 구분한다. 문자열의 `<`와 `>`는 UTF-8 byte 순서를 사용한다. Binary 값은 16진수로 입력한다.
- 비교 연산자와 `contains`는 Null 셀과 일치하지 않는다. Null 셀은 `null` 연산자로 선택한다.
- 필터가 있는 컬럼의 헤더 이름은 강조 색으로 표시한다.

### 정렬

- 헤더를 클릭할 때마다 오름차순, 내림차순, 정렬 없음 순으로 순환한다. 헤더 컨텍스트 메뉴에서는 방향을 지정하거나 바로 해제한다. 정렬 키는 컬럼 하나다. 다른 컬럼의 헤더를 클릭하면 그 컬럼의 오름차순으로 바뀐다. 헤더에는 `▲` 또는 `▼`로 방향을 표시한다.
- 필터가 있으면 통과한 행만 정렬한다.
- 방향과 관계없이 Null은 마지막에 둔다. 같은 값의 행은 원본 파일 순서를 유지한다.
- 문자열은 UTF-8 byte 순서로 정렬하고, 부동소수점 NaN은 가장 큰 값으로 정렬한다.
- `Struct`, `List`, `Map` 및 표시를 지원하지 않는 타입의 컬럼은 정렬하지 않는다. 해당 헤더를 클릭하면 필터 및 정렬 바에 정렬할 수 없다는 알림을 표시한다.

### 파일 구조

- 탭 바의 `Data`와 `File Structure`로 전환한다. 탭마다 선택을 기억하며 `Ctrl+F`는 데이터로 돌아가 찾기를 연다.
- 파일 요약, 컬럼 저장 정보, Row Group을 확인한다. Row Group을 선택하면 해당 그룹의 컬럼 정보를, `All`은 합산 정보를 표시한다. 잘린 셀에 마우스를 올리면 전체 내용과 인코딩을 확인할 수 있다.
- 파일에서 잘린 통계에는 `≈`, 통계가 없거나 중첩 leaf이면 `-`를 표시한다. Null 수는 모든 Row Group에 기록되어 있을 때만 합산한다.

### 테이블 구조

- SQLite 탭의 `Table Structure`에서 테이블·뷰 정의, 행 순서, 컬럼, 인덱스, 데이터베이스 속성을 확인한다.
- 컬럼 정보에는 선언 타입과 저장된 값에서 정한 Arrow 타입을 표시한다. 테이블의 `CREATE` 문은 인덱스 옆에 표시하고, 인덱스에 마우스를 올리면 `CREATE INDEX` 문을 표시한다.

## 질의와 메시지 파일

질의는 활성 Parquet 또는 SQLite 탭에 적용한다. 메뉴, 질의 창, 메시지 파일은 같은 필터·정렬·찾기 상태를 갱신한다.

### 질의 텍스트

질의는 행 뷰와 찾기 값을 텍스트로 표현한 것으로, 한 줄에 명령 하나를 쓴다. 필터 및 정렬 바는 조건을 이 형태로 표시하고, 컨텍스트 메뉴는 항목 레이블에 사용하며, `Copy Query`는 이 형태로 출력한다.

```text
find 홍길동
filter age >= 30 and status == "활성"
sort -created_at
```

- `find <value>`는 값 전체가 해당 값과 같은 셀을 찾는다.
- `filter <expression>`은 식을 만족하는 행을 남긴다. 위 필터 형태처럼 조건을 `and`로 연결하고 같은 컬럼의 조건은 `or`로도 연결한다. 한 단계에서는 한 종류의 연결어만 사용하므로 `and`와 `or`를 섞으려면 괄호가 필요하다. 예: `filter (a == 1 or a == 2) and b == 3`. `or`만 있는 줄에는 괄호가 필요 없다. 예: `filter a == 1 or a == 2`. 여러 `filter` 줄은 `and`로 합친다.
- 서로 다른 컬럼 사이의 `or`, `or` 내부의 `and`, 괄호 없는 혼합은 해당 위치를 가리키는 오류가 된다.
- 출력한 질의는 바에 표시한 것처럼 여러 조건이 있는 절을 각각 괄호로 묶는다.
- 조건은 `==`, `!=`, `<`, `<=`, `>`, `>=`, `contains`를 사용하는 `<column> <op> <value>` 또는 `<column> is null`, `<column> is not null`이다. `=`는 `==`로 읽는다. 연산자는 위 필터 표처럼 컬럼 타입을 따른다.
- `sort <column>`은 오름차순, `sort -<column>`은 내림차순으로 컬럼 하나를 정렬한다. 질의에는 `find`와 `sort` 줄을 각각 최대 하나씩 넣을 수 있다.
- 공백이 없는 값은 그대로 쓰고, 나머지는 `"…"`로 인용하며 `\"`, `\\`, `\n`, `\t`, `\r` escape를 사용한다. 다른 역슬래시는 그대로 유지하므로 Windows 경로를 변경 없이 다시 읽는다. 문자열 컬럼의 값은 항상 인용해서 출력한다.
- 공백이나 기호가 있는 컬럼 이름은 backtick으로 감싸고 내부 backtick은 두 번 쓴다. 예: `` `운행 일자` ``. 이름은 정확히 일치해야 하며 대소문자만 다른 이름은 오류에서 제안한다.
- 키워드는 대소문자를 구분하지 않고 빈 줄은 무시한다. 질의는 뷰 전체를 명시한다. 줄이 없으면 해당 찾기·필터·정렬을 없애고 빈 질의는 모두 해제한다.
- 값은 메뉴 조건과 같은 규칙으로 컬럼 타입에 맞게 파싱한다. 오류에는 줄, 문자 열, 이유를 표시한다. 예: ``line 1, column 8: this `(` is not closed``.
- 질의를 출력하고 다시 읽으면 같은 조건·정렬·찾기 값을 얻는다.

### 질의 입력과 로그

질의는 활성 Parquet·SQLite 탭의 필터·정렬·찾기를 대체한다. 파싱 오류가 나면 기존 상태를 유지하고 줄·열·이유를 표시한다. 새 조건과 함께 보낸 찾기는 조건이 적용된 뒤 실행한다.

Windows에서는 `Query → Write Query…`로 현재 질의를 편집한다. `Ctrl+Enter` 또는 `Apply`로 적용하고 창을 유지하며, `Esc` 또는 `Close`로 닫는다. 창을 다시 열면 활성 탭의 현재 질의를 다시 채운다.

외부 프로그램은 `Copy Message File Path`로 경로를 얻어 파일에 UTF-8로 질의 전체를 쓴다. UTF-8 BOM과 CRLF 줄 끝을 허용한다. 파일이 안정되면 적용하며 viewer가 종료되면 파일을 제거한다.

| 플랫폼 | 앱 저장 디렉터리 |
|---|---|
| Windows | `%LOCALAPPDATA%\TPUI` |
| Linux | `$XDG_STATE_HOME/tpui`. 설정이 없으면 `~/.local/state/tpui` |

메시지 파일은 이 디렉터리의 `inbox/<process id>.txt`를 사용한다. 질의와 파싱 오류는 `query-log/<date>.jsonl`에 소스·질의·결과 또는 오류와 함께 추가한다. 행 뷰 질의는 완료 시 기록하며, 대체된 계산이나 조건이 바뀌지 않은 클릭은 기록하지 않는다.

`Open Query Log Folder`로 로그 위치를 연다. 로그에는 질의에 사용한 셀 값을 포함한 질의 텍스트가 남으며 사용자가 삭제할 때까지 유지한다.

## 테마와 사용량

### 테마

- 밝은 색과 어두운 색 구성을 제공한다. 시작할 때 Windows 앱 색상 설정을 따르고 이후 변경도 계속 반영한다. 도구 모음의 `Light Mode` / `Dark Mode` 버튼으로 테마를 바꾸면 다시 시작할 때까지 시스템 설정을 더 이상 따르지 않는다.

### 메모리와 CPU 사용량

- Windows에서 상태 표시줄의 `Usage`를 누르면 새 사용량을 표시한다. 다음에 누를 때까지 표시값을 유지한다.
- 메모리는 viewer와 코드·PDF 프로세스의 working set 합계이며 GPU 메모리는 제외한다. CPU는 직전 측정 이후 전체 시스템에서 이들이 사용한 비율이다.
- 일별 측정값은 [앱 저장 디렉터리](#질의-입력과-로그)의 `usage-log/<date>.jsonl`에 저장한다. JSON Lines로 열어 확인하고 오래된 로그는 직접 삭제한다. 기록하지 못한 측정값에는 `not logged`를 표시한다.
